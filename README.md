# ZeroSol専用 営業・販売・在庫管理プラットフォーム（デモ）

ZeroSol本部の商品・在庫・見積・受注・出荷管理と、販売店の営業支援をつなぐプロトタイプ。表示データ・商品規格・価格は架空です。

## 起動

Node.js 22以上。外部パッケージ・APIキー・DBは不要。

```sh
cd /workspace/ZeroSol-home
npm run dev
```

既定ポートは3000。別ポートは `PORT=3002 npm run dev`。検証は `npm test`。

## デモの流れ

1. 初期表示はZeroSol本部。「商品・在庫」で本部倉庫の実在庫・引当済・販売可能数・補充目安を確認。
2. 「入出庫登録」で増減数量と理由を登録。プラスは入庫、マイナスは出庫・棚卸減。
3. 「見積登録」で販売店向け見積の件名・宛先・有効期限・商品明細を登録。税率10%、消費税は小計に対して切り捨て。
4. 見積詳細で「受注登録・在庫引当」。在庫が不足する場合は処理を拒否。
5. 「出荷を記録」で実在庫と引当数を同時に減算。出荷前の受注取消では引当のみ解放。
6. 本部／販売店を切り替えると、在庫と見積は所有者ごとに別表示。会社間の受発注や在庫は自動同期しない。
7. 従来の案件・現場調査・概算試算・技術相談も利用可能。販売店案件から自社顧客向けの明細見積を登録できる。

本部が販売店の案件と見積を関連付ける場合、顧客情報の共有に同意した案件のみ候補に表示します。案件の進捗変更と受注・出荷記録は独立しており、自動で同期しません。

## 在庫と見積の区別

- メーカー在庫と販売店在庫は別の所有者・倉庫。
- ZeroSol→販売店の見積と販売店→顧客の見積は別の取引。
- 在庫明細の数量単位は巻・缶・台。面積による既存の概算試算から自動転記しない。
- 非在庫の施工費は金額に含めるが、在庫引当の対象外。
- 「概算・提案支援」は参考試算。「見積登録」は明細保存。正式な承認・発行・送信は未実装。
- 出荷済金額は出荷した登録見積の税込合計。会計上の売上や入金額を表すものではない。

## 制限

保存先はブラウザのlocalStorageのみ。認証・サーバー権限・会社間連携・メーカー通知・正式見積承認・仕入発注・請求・入金・返品・複数倉庫移動は未実装です。写真は一時プレビューのみで保存されません。役割切替は表示デモでありセキュリティ境界ではありません。複数利用者・タブ間の同時更新に対応しません。実際の顧客情報・在庫・機密情報を入力しないでください。

旧デモの案件データは保持し、追加の販売管理データは別キー `zerosol-sales-v1` に保存します。ブラウザのサイトデータ削除で初期化できます。

本番化では販売店別データ分離、共有同意、監査ログ、商品・取引先マスターの承認、同時更新でも過剰引当しないサーバー側処理が必要です。
